## Application and supply-chain review

- The only billable integrations are the two OpenAI Responses adapters. This PR makes both deployed entry points import only a [disabled response handler](../server/disabled-photo-route.ts#L4). The deployed functions no longer import the local request handler, provider adapters or key configuration. Their POST behavior remains a no-store 503, and other methods receive 405. Local analysis still requires opt-in, a loopback connection and server credentials. Tests provide simulated provider responses explicitly. Production has manual catalog matching and room-floor alignment.
- [Local upload validation](../server/image-validation.ts#L7) bounds the image bytes, format, dimensions and certain header/chunk structure. [The request handler](../server/photo-handler.ts#L18) limits JSON and upload time, applies a local request limit and serializes provider work per handler. The [furniture adapter](../server/photo-analysis.server.ts#L12) and [room adapter](../server/room-photo.server.ts#L21) use a fixed HTTPS destination, disable redirects, bound output and time, and return sanitized errors. Neither accepts remote image URLs or calls tools based on image instructions. Model output enters [bounded parsing](../src/lib/photo-search-types.ts#L19) and [room validation](../src/lib/room-photo-types.ts#L14), then React text and numeric geometry. A model can still produce incorrect classifications or footprint estimates.
- Manual room photos stay in browser memory. [The planner](../src/components/RoomPlanner.tsx#L78) limits selected files by MIME and compressed bytes, and [the floor loader](../src/lib/floorPhoto.ts#L14) releases textures on replacement or unmount. Large decoded images can still consume browser/GPU memory. Header checks are not a full decoder or malware scan. Optional local furniture analysis sends the original encoded image, which may carry metadata. Consider image resizing and metadata removal before any public paid AI launch. No app-managed upload store, public upload URL or temporary server file was found.
- Catalog names are React text. Product images ship with the app and retailer links open in the browser. There is no runtime external catalog parser, secret-bearing catalog feed, or server-side URL fetch. No furniture price, measurement or verified product record changed.
- The accessible history comprised 32 baseline commits, all 11 PR heads, and 306 local blobs/commits including deleted files and unreachable blobs. The revised scanner includes commit/tag data and unquoted known provider assignments. No credential was identified after confirming the exact historical placeholder. Only `.env.example` appeared on tracked historical environment paths. Unfetched forks and secrets stored elsewhere remain outside this test.
- npm reported zero known advisories at review time. The existing workflow uses pinned actions, a read-only token, disabled installation scripts and mock-only tests. The production build check adds a deliberately misprefixed key canary and enables the stale public flag during the build. The resulting assets contain neither the canary nor the experimental button. GitHub branch rules, external logs and billing configuration remain unverified.

## Verification

- **193 tests across 26 suites passed**, including direct route denial before body reads, mock-only local image analysis, upload limits, shared placement, dimensions, rotation/removal and all 19 HTTPS retailer URLs. TypeScript, production build, artifact checks, Git history scans and npm audit also passed. Vite retained its existing large Three.js chunk advisory.
- The local production build had a working WebGL canvas. In Chrome I changed the room width, found a POÄNG chair through manual matching, checked its retailer URL, placed and rotated it, switched to top-down view, saw a $149 total and removed it to restore the $0 total.
